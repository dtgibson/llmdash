# Change Brief — Tailnet Bind and Reporting Resilience

## What is changing
Two bounded hardenings. (1) The shipped network default moves from "LAN + tailnet" to **tailnet-only**: the server keeps its single wildcard listener (so the badge and the deploy health check on `127.0.0.1` keep working) but closes every TCP connection at accept unless it *arrived on* a loopback or Tailscale address *from* a loopback or Tailscale source; a new `LLMDASH_ALLOW_LAN=1` restores today's behavior, `LLMDASH_HOST=127.0.0.1` stays the local-only option, and a pinned `LLMDASH_HOST` keeps its exact current meaning. (2) The Claude model-cap ("Fable") and Codex reset readings stop disappearing silently: the `/usage` probe is allowed to refresh aged model caps during active use, probe-captured caps survive the newest-wins race, an aged-out cap is disclosed instead of the UI claiming a "complete current reading", Codex readings carry a freshness band and a per-window `window-not-reported` diagnostic, the current Codex `window_minutes` duration key is recognized, reset-credit facts degrade to `stale` (never `unsupported`) when polls fail, and the badge stops reading "resets now" forever on a passed reset.

## Why now
The user ratified the ROADMAP "Optional strict tailnet-only binding by default" item and, in the same breath, reported that Fable limits and Codex resets are not always visible. Live evidence on this Mac (2026-09-05, read-only): `/api/state` shows Codex `five_hour: null` with `limitsDiagnostic: null` and `freshness: null` (the 5-hour window has been absent from every complete app-server response since 2026-09-03T22:10Z — the last `codex/five_hour` snapshot row); the only Fable cap on file is `used 100%, resets_at null, captured 2026-09-04T16:10Z` (11 h old) while the file-level `capturedAt` is 2 min old; `/tmp/llmdash.err` holds 23 `parse-failed` + 6 `timeout` probe lines that never surface in the UI because the account reading is kept fresh by the statusline.

## User-facing impact
**Part 1 is user-visible in exposure terms:** a device on the LAN (not on the tailnet) that could open `http://<lan-ip>:8787` today will be refused after this change; a tailnet peer that reaches this machine via its LAN IP (e.g. a `.local` Bonjour name) must switch to the tailnet IP / MagicDNS name or the owner sets `LLMDASH_ALLOW_LAN=1`. The current peer `snowravendev-vm` resolves to `100.82.9.81` via MagicDNS, the badge uses `127.0.0.1`, and the deploy health check uses `127.0.0.1` — none are affected. Disclosed in the startup banner, `healthLines()`, the README (Run it / Reset & billing / Configuration), and the plist example comment. Part 2 changes copy and diagnostics only, inside existing surfaces: Codex gains the existing aging/stale pill; an unavailable Codex window names its cause; an expired Fable cap is named instead of the "standard account windows … remain the complete current reading" claim; the badge dropdown shows `—` instead of `now` for a passed reset.

## Design pass
Not needed — no visual change. Every Part 2 surface reuses an existing component and slot (the freshness pill, the unavailable-card `limit-meta` line, the `limitsDiagnostic` note, the `empty-evidence` paragraph, the badge's existing text-row helper); only copy strings and enum-code→copy tables change.

## Scope
**Part 1 — approach (b): wildcard bind + accept-time address gate.** Chosen over two listeners because (i) a gate on both `socket.localAddress` and `socket.remoteAddress` gives the same protection as an IP bind under the weak-host model, and (ii) it needs no re-bind lifecycle when `tailscale0` is DOWN at boot (2026-06-22): with the tunnel down only loopback clients can connect, nothing widens, and tailnet clients are accepted the moment the tunnel is up. **Changes:** `config.js` (new `allowLan` from `LLMDASH_ALLOW_LAN`, only `1`/`true` enable; `host` default unchanged); `src/net.js` (add `canonicalIp`/`isLoopback`/`isTailnetIp` lifted from `reset-billing-api.js`, a pure `isTrustedConnection({localAddress, remoteAddress}, policy)`, and `networkScope(cfg, tailnet)` → `tailnet-only | lan-and-tailnet | pinned:<host>`); `src/server.js` (`server.on('connection')` destroys an untrusted socket before any HTTP bytes when the bind is a wildcard and `allowLan` is off; startup banner states the scope, the tailnet-down fallback, and the two knobs); `src/health.js` (`networkScopeLine()` added to `healthLines()`, naming an ignored `LLMDASH_ALLOW_LAN` when `LLMDASH_HOST` is pinned — the `hostsConfigLine` precedent); `src/reset-billing-api.js` imports the lifted helpers; `README.md` lines 77, 216, 636–639 and `macos/com.llmdash.dashboard.plist.example` comment; `tests/net.test.js` + a new `tests/bind-scope.test.js`. **Does NOT change:** `scripts/menubar/*` (`LLMDASH_BADGE_HOST` default `127.0.0.1`), `pipeline.config.json` health check, `src/hosts.js` `fetchPeerState`/`isLocalHost`, `scripts/install-macos.sh` service/plist generation, the reset-billing route rules, `/api/*` payloads.
**Part 2 — Claude model caps (root cause: the only producer is starved, then evidence ages out unannounced).** FM-C1 `src/claude-refresh.js:95-98` returns `'fresh'` whenever the statusline wrote within 5 min, so during active use the `/usage` probe — the sole `model_limits` producer (`scripts/statusline.js:21` writes account windows only) — never runs; caps then expire via `src/claude-limits.js:63-69` (reset passed, or 7-day resetless TTL) and `public/app.js:669` asserts a "complete current reading". Hardening: a model-cap-age condition in `maybeRefreshClaude` (probe allowed when the newest active cap is older than a fixed `MODEL_LIMIT_REFRESH_MS`, e.g. 60 min — activity gate, single flight, cadence floor, backoff all preserved; no new env knob); new lowest-precedence `limitsDiagnostic` codes `model-cap-expired` (with `model`, `lastCapturedAt`) and the existing `auto-refresh-failing` cause surfaced in the model-cap block copy (`app.js` ~660-671, menubar `DIAG_LINES`, own-key lookups); FM-C2 `claude-refresh.js:847` drops a probe's fresh `model_limits` when a statusline write wins the timestamp race → merge caps regardless of who wins the `rate_limits` race; FM-C3 `claude-limits.js:65` and `claude-refresh.js:807` expire a cap the instant `resets_at` passes with no skew grace → apply `MODEL_LIMIT_CLOCK_SKEW_MS`; FM-C4 `public/app.js:967-968` skips a peer cap with no `capturedAt` → fall back to the member tool's `dataAt`. Out of scope: parser rewrite for the 23 `parse-failed` probes (flagged), badge-glyph semantics (2026-07-11).
**Part 2 — Codex resets (root cause: absent/stale evidence renders as if current, with no cause).** FM-X1 `src/server.js:209-210` forces `limitsDiagnostic: null` whenever any window exists, so a complete response omitting `five_hour` renders "Unavailable / No short-window reading / RESET · —" with no cause (`app.js:430-436`) → `window-not-reported` per-window code carrying `lastSeenAt` from the previous complete in-process reading (never a value; no snapshot backfill), plus ONE bounded stderr line on the present→omitted transition naming slot key names only; FM-X2 `server.js:181` sets `codex.freshness = null` while `readCodexLimits` (`codex-limits.js:466-491`) retains `lastCompleteReading` forever on timeout/spawn-error/exit → populate `freshness` from `cachedCodexLimits().capturedAt` with poll-derived bands (fresh ≤ 2 polls, stale > 5 — the device-health precedent), so the existing pill machinery applies; FM-X3 `WINDOW_DURATION_FIELDS` (`codex-limits.js:283-288`) lacks `window_minutes`, the key the installed Codex 0.153.0 emits (13 hits in the binary, every rollout event on this Mac: `"primary":{"used_percent":0.0,"window_minutes":300,…}`) → add it (and only it; `resetsInSeconds`-style relative fields have zero hits and are not added); FM-X4 `fresh()` (`codex-limits.js:54-56`) returns `undefined` past the 5-minute `ACCOUNT_FACT_TTL_MS`, so five failed polls flip reset credits to `unsupported` while the gauges keep rendering → past TTL emit `stale` with `observedAt` age, hard-cap at 24 h; FM-X5 `scripts/menubar/llmdash.5s.js:597` feeds a passed reset into `fmtDur` (`'now'` forever) where `app.js:376` shows `—` → guard in `windowRowText` (`fmtDur` itself stays VERBATIM for the parity test). Out of scope: reading `rateLimitsByLimitId` (a new per-limit map in Codex 0.153.0 — new data, flagged), FM-8 plan-enum clearing (by design per CLAUDE.md).
