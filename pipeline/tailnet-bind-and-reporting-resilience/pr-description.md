## Tailnet Bind and Reporting Resilience

### What this does
Two bounded hardenings, no data-model change beyond one ratified pin. **Part 1** moves the shipped network default from "LAN + tailnet" to **tailnet-only**: the server keeps its single wildcard listener (so the menu-bar badge and the deploy health check on `127.0.0.1` keep working) but destroys any accepted TCP connection at accept time — before a single HTTP byte is parsed — unless it arrived on a loopback/Tailscale address *from* a loopback/Tailscale source. `LLMDASH_ALLOW_LAN=1` restores today's reachability; a pinned `LLMDASH_HOST` keeps its exact current meaning (no gate). **Part 2** stops the Claude model-cap ("Fable") and Codex reset readings from disappearing silently: the `/usage` probe may refresh aged caps during active use (FM-C1), probe caps survive the statusline's newest-wins race (FM-C2), a passed reset gets the 5-minute skew grace (FM-C3), a clockless peer cap inherits its tool's `dataAt` (FM-C4); Codex ships a per-window `window-not-reported` diagnostic with `lastSeenAt` (FM-X1), poll-derived `freshness` bands (FM-X2), recognizes the installed `window_minutes` key (FM-X3), degrades reset credits to `stale` instead of `unsupported` (FM-X4), and the badge shows `—` instead of "resets now" forever on a passed reset (FM-X5).

### How to test
1. `npm test` — the whole suite is green (baseline 815 pass / 2 skipped, plus the new tests; the exact counts are in the hand-back).
2. `npm start` and read the startup log: the `Data sources:` block and the banner both carry a `Network: bound to 0.0.0.0:8787, TAILNET-ONLY (the default) …` line naming the tunnel-down fallback and the two knobs.
3. `curl -fsS http://127.0.0.1:8787/api/state | head -c 200` succeeds; `curl http://<this-machine's-tailscale-ip>:8787/api/state` from a tailnet peer succeeds; `curl http://<this-machine's-LAN-ip>:8787/` from a LAN device (or from this machine) is refused with an empty reply, no HTTP status.
4. `LLMDASH_ALLOW_LAN=1 npm start` → the banner reads `… with LLMDASH_ALLOW_LAN=1 — reachable from the LAN and the tailnet …` and the LAN curl succeeds. `LLMDASH_HOST=192.168.x.y LLMDASH_ALLOW_LAN=1 npm start` → `… (LLMDASH_HOST pinned) … LLMDASH_ALLOW_LAN is set but IGNORED …`.
5. In `/api/state`: `tools[codex].freshness` is now `{capturedAt, freshForMs: 120000, staleAfterMs: 300000}` (2 × / 5 × `LLMDASH_POLL_MS`); when the live Codex response omits `five_hour`, `tools[codex].limitsDiagnostic` is `{reason:'window-not-reported', window:'five_hour', lastSeenAt}` and the dashboard's 5-hour card reads "Not in the latest Codex response · last reported …"; when a Fable cap has aged out, `tools[claude-code].limitsDiagnostic` is `{reason:'model-cap-expired', model, lastCapturedAt[, cause]}` and the "Claude model caps" block names it instead of claiming a complete reading.
6. Badge dropdown: a passed reset renders `resets —`; `window-not-reported` / `model-cap-expired` appear as sanitized diagnostic rows; `auto-refresh-failing` now names its cause.

### Notes for reviewer
- **Ratified default change (user-visible exposure):** a LAN device that is not on the tailnet loses access; a tailnet peer that reaches this machine via a `.local`/LAN address must switch to the Tailscale IP / MagicDNS name, or the owner sets `LLMDASH_ALLOW_LAN=1`. The current peer (`snowravendev-vm` → `100.82.9.81` via MagicDNS), the badge (`127.0.0.1`), and the deploy health check (`127.0.0.1`) are unaffected. Disclosed in the banner, `healthLines()`, README (Run it / Reset & billing / Configuration), and the plist example comment; pinned by `tests/bind-scope.test.js`.
- **Gate mechanics:** `server.on('connection')` runs at accept, ahead of the first `data` tick, so the http parser never sees a refused socket's bytes (zero response bytes — proven with a real socket through the injectable `_setConnectionGate` seam so the test needs no tailnet interface). `canonicalIp`/`isLoopback`/`isTailnetIp` were lifted verbatim from `reset-billing-api.js` into `src/net.js`; `isTrustedResetBillingAuthority` is byte-equal and `tests/reset-billing-api.test.js` is untouched. Missing/undefined addresses and an absent policy fail closed.
- **Ratified pin update:** `tests/state-unchanged.test.js:82` (`codex.freshness === null`) now asserts the Claude key set `['capturedAt','freshForMs','staleAfterMs']` with poll-derived thresholds; the top-level and per-tool key-set guards are byte-for-byte unchanged. `tests/claude-freshness.test.js` "codex carries no freshness treatment" was rewritten to the same effect.
- **`model-cap-expired` evidence source:** the reading file drops expired caps on the next write (pinned by ratified tests in `claude-refresh-parse.test.js`), so the "last observed" evidence comes from the poller's existing SQLite snapshots (`claude-model:<slug>` rows) via a new `getLatestModelSnapshots()` — disclosure only, never a revived value, bounded to 30 days (`MODEL_LIMIT_EXPIRED_DISCLOSURE_MS`) and 256 rows. The `cause` field rides along at the same 3-failure threshold as `auto-refresh-failing`.
- **FM-C1 bound:** in cap-age mode attempts are spaced by `MODEL_LIMIT_REFRESH_MS` (60 min, a constant — no env knob), so a cap the pane no longer renders cannot re-arm a probe every 5-minute cadence-floor tick. Residual: with zero active caps (a cap that already expired and was dropped from the file) the literal "newest active cap" condition has nothing to age, so during continuous use the probe still waits for the account reading to go stale — the brief's stated condition, noted as a limitation.
- **FM-C2:** when the current file is newer, only the model caps merge (per key, newest `captured_at` wins, payload wins ties); the account windows keep the organic capture. `writeReadingIfNewer` returns `false` when the merge changes nothing, so the parse-test expectations on the return value hold.
- **FM-X4:** the `stale` status masks `zero`/`partial` for the pill; the client still derives counts/expirations from the raw fields, so nothing is lost visually. Plan/credit facts keep their existing 5-minute `fresh()` (only reset credits were in scope).
- **`fmtDur` is verbatim** (parity test green); the FM-X5 guard lives in `windowRowText`.
- Out of scope, noticed: the 23 `parse-failed` probes (parser rewrite), `rateLimitsByLimitId` in Codex 0.153.0, and the plan-label TTL — all flagged, none changed.
